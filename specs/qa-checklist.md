# 콘텐츠 QA 체크리스트 (독립 검수 — 만든 사람이 아닌 눈으로)

먼저 `specs/agent-brief.md`(함정 목록)와 `specs/content-guide.md` 를 읽어요. 그다음 맡은 파일의 **레슨·문제를 하나도 빠짐없이** 학습자 입장에서 풀어 보듯 검토해요.

## 1. 정확성 (가장 중요)
- [ ] 영어 문장이 문법적으로 맞고 **원어민이 실제로 쓰는 자연스러운 표현**인가 (어색하면 고침)
- [ ] 한국어 뜻(ko)이 영어와 **정확히 같은 뜻**인가 (시제·주어·존댓말 수준·뉘앙스)
- [ ] 설명(html·why·tip·note·terms)이 **사실로 맞는가** — 발음 설명(한글 표기 포함), 문법 규칙, 예외. 예: 「o는 아」처럼 맥락 없이 오해를 부르는 설명은 보충(미국/영국 차이, 짧은/긴 소리 구분 등)
- [ ] 정답 데이터가 맞는가: choice 의 ans, match 짝, fill 의 빈칸 답, cards 순서, listen/dictation 의 say 와 보기

## 2. 공정한 채점 (학습자가 억울하지 않게)
- [ ] `choice`/`listen`: **정답이 정확히 하나**인가 (다른 보기도 맞을 수 있으면 보기를 바꿈)
- [ ] `type`/`fix`/`order`/`build`/`dictation`: 학습자가 쓸 법한 **다른 정답**을 3~5개 떠올려 실제 채점기로 시험 → 떨어지면 answer 에 추가. 시험 방법:
  ```
  node -e "import('./tools/load_content.mjs').then(({load})=>{const C=load('코스id');const p=C.Content.problem('문제id');console.log(C.Grader.text('학습자 답', C.Content.answers(p)))})"
  ```
- [ ] `fix`: 틀린 문장이 **정말 틀렸고**, 고칠 곳이 분명한가 (여러 군데 다 고쳐야 하면 prompt 에 밝힘)
- [ ] `order` 함정 카드가 **정답 문장에 끼워도 맞는 문장**이 되지 않는가
- [ ] `fill` 빈칸에 들어갈 수 있는 다른 맞는 답(축약형·동의어)이 a 목록에 있는가
- [ ] `ko` 를 보고 쓴 영어가 answer 의 대표 답과 시제·인칭이 일치하도록 ko 가 충분히 구체적인가

## 3. 학습 흐름
- [ ] 문제가 **레슨에서 설명한 내용**으로 풀 수 있는가 (안 배운 문법·낱말이 갑자기 나오면 설명을 보충하거나 문제를 바꿈)
- [ ] 힌트 3단계가 방향 → 구체 → 정답 순서이고 **틀린 정보가 없는가**
- [ ] 같은 레슨 안 쉬움 → 어려움 순서
- [ ] 보스(상황 미션) 문제들이 이어지는 이야기로 자연스러운가
- [ ] roles 색(S V O C M J Q)이 문장 성분을 **바르게** 표시하는가 (틀리면 고치거나 roles 를 뺌)
- [ ] 말투 ~해요체, 오타·띄어쓰기

## 4. 기록
- 고친 것은 전부 `qa/<코스id>.md`(덱은 `qa/deck.md`)에 표로 남겨요: | id | 문제 | 고친 내용 |
- 판단이 어려운 것(사용자에게 물어봐야 할 것)은 같은 파일 맨 아래 「질문」 절에.
- 끝나면 `node tools/stamp.mjs && node tools/validate_content.mjs && node tools/check_answers.mjs` FAILS 0 (남의 파일 실패는 무시).
- 맡은 파일 외에는 수정 금지(다른 에이전트가 동시에 작업 중). git commit/push 금지.
